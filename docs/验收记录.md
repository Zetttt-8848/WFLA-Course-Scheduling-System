# v0.2.0 验收记录

本轮使用Windows/Python3.13.5、Intel Core Ultra 5 125H；所有学生、教师、分班与实验室样例均为虚构。新增的学校规则来自需求方，本机实际名单未被导入或上传。

## 检查结果

- 42项pytest测试全部通过，包含原27项回归和新增年级开放节次、公共课分工、逐人周总量、自修准确课时、跨年级共享座位、办公室排除、简化Excel组合导入及原子失败、师资不重复计算、四类视图和导出列序。
- 已预分班且可用时间相同的8名学生，面对两间各4座自修室，仍可分流为每室4人、各5节；用于防止加速时误将整组绑定到一间教室。
- 与房间池相关的容量约束、公共课和自修结果均由独立检查器从实际房号重新计算，未通过审计的结果不作为有效课表导出。
- 浏览器已完成新规则演示载入、按钮排课和个人课表展示，11年级周五第9节关闭，课表含TOK、五项公共课及自修；页面仅显示节次。
- 新输入的完全自动分班（删除演示预分班）小实例也找到有效解；不以此保证全规模性能。

## 性能与限制

12人新规则小样例在网页首解试验约5.11秒完成，零硬冲突。网页演示已改为使用60秒预算继续优化，不再默认找到首解即结束。最终版本12人网页输入在20.423秒取得OPTIMAL，18个学科教学班，教室代价80、每日集中超额8，独立审计零冲突；最优性仅针对文档所列三个目标与当前候选范围。新版完整Excel输入亦已通过往返检查。

264人（11/12各132人）预分班压力样例，在120秒试验中返回UNKNOWN，未找到可交付方案，也未证明无解。新版全规模分钟级目标尚未达成，不能使用下方旧六区块模型396人约23秒的记录宣称新版达标。候选班数、教师上限与实际学校资源都会影响搜索，需要真实资源配置及更多不同选课分布后再评估。

尚缺实际实验室房号/能力、C楼普通备用房、实际座位容量复核、G10每日节次/自修课时、G12剩余1节的用途。它们没有被系统静默猜成已确认数据。

# 本机 MVP v0.1.0 验收记录

此记录对应本次本机开发检查。测试数据完全虚构，无真实学校名单。

Windows，Python 3.13.5，Intel Core Ultra 5 125H。CP-SAT 使用 8 个搜索工作线程，固定随机种子 42。已在独立虚拟环境安装 `requirements-dev.txt`，`pip check` 无损坏依赖。

## 已执行检查

- 27 项 pytest 测试全部通过，包括六区块覆盖、自动分班与自动区块、三年级政策、四门 HL 特批、固定活动冲突、教师禁排导致无解、独立审计对故意冲突的检出、Excel 往返、公式拒绝、四视图和导出、版本保留、CSRF 及手动调课拒绝冲突。
- 命令行完成：生成 Excel 演示 → 校验 → 求解 → 独立审计 → Excel 导出。
- 实际浏览器完成虚构数据载入、后台排课，并显示学生六区块课表；其他视图与下载同时由接口测试检查。
- 本地 `/health` 返回 v0.1.0 正常状态。

## 规模试验

| 学生总数 | 数据含义 | 结果 | 建模与求解耗时 |
|---|---|---|---|
| 36 | 三个年级各12人，快速体验样例 | 可行，独立审计零硬冲突 | 约1秒 |
| 132 | 三个年级各44人，中等样例 | OPTIMAL，独立审计零硬冲突 | 1.693秒 |
| 396 | 三个年级各132人，164个预设教学班 | OPTIMAL，独立审计零硬冲突 | 23.457秒 |

上述演示使用预设的六区块时段、教学班及学生分班，教师、实际课次和房间由求解器计算。它们验证有预设输入的联合资源排课能力，不代表任意选课、完全自动分班和自动区块都可在同样时间内完成。完全自动模式另有小实例测试，尚未完成无预设的全规模性能验收。

较大样例首次试验在120秒内未得出结论。随后移除严格六区块已蕴含的冗余学生区间约束（仍保留固定活动/禁排检查），并加入固定区块窗口的教师/教室总容量必要约束，得到表中结果。所有成功结果均再经独立检查器审计。多线程搜索耗时可能变化。

`OPTIMAL` 在此仅涉及当前候选范围内的班数目标；演示预设教学班已经确定班数，不表示教学质量软目标最优。
